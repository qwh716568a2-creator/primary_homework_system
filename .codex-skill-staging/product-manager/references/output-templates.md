# Product Output Templates

Use these templates only when the user needs a more formal artifact than the default response structure.

## Problem Brief

Use when the request is still ambiguous and needs framing before solutioning.

- Background
- Problem statement
- Who is affected
- Current pain point or failure mode
- Why now
- Assumptions
- Open questions
- Recommended next step

## PRD or MVP Brief

Use when a direction is already chosen and the user needs a delivery-ready requirement.

- Background and objective
- Success metrics
- Target users
- Core scenario or user journey
- Scope
- Out of scope
- Functional rules
- Edge cases and exceptions
- Dependencies
- Risks
- Acceptance criteria

## User Story Pack

Use when engineering or design needs implementation-ready slices.

- Story
- User value
- Trigger
- Main flow
- Edge cases
- Acceptance criteria
- Notes for design, engineering, and QA

## Experiment Plan

Use when the key question is whether an idea should scale or ship.

- Hypothesis
- User segment
- Variant or intervention
- Primary metric
- Guardrail metrics
- Duration or stop condition
- Success threshold
- Follow-up decision rule

## Release Readiness Note

Use when the user needs a concise launch-oriented summary.

- What is changing
- Who it affects
- Risks
- Rollout plan
- Monitoring plan
- Rollback trigger
- Communication needs
