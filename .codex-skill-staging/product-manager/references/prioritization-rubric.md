# Prioritization Rubric

Use this reference when the user asks what to do first, what to cut, or how to compare competing requests.

## Lightweight Scoring

Score each candidate on four dimensions:

- User value: How much pain is reduced or value is created.
- Business value: How much it helps revenue, retention, adoption, cost, or strategy.
- Effort: Delivery cost across product, design, engineering, and QA.
- Risk or uncertainty: Unknowns, dependencies, compliance, or rollout risk.

Recommend one of these outcomes:

- Do now: High value and manageable effort or risk.
- Do next: Valuable, but blocked by sequencing or capacity.
- Explore first: Promising, but too uncertain to commit immediately.
- Defer or cut: Low value relative to cost or distraction.

## RICE Shortcut

Use when the user wants a more explicit framework.

- Reach: How many users or events are affected.
- Impact: How strongly the outcome changes behavior or business value.
- Confidence: How reliable the evidence is.
- Effort: Relative delivery cost.

If exact numbers are unavailable, use directional labels such as high, medium, and low and explain the reasoning.

## MoSCoW Shortcut

Use when the user is deciding scope inside a fixed deadline.

- Must have: Without this, the release fails its core purpose.
- Should have: Important, but not release-blocking.
- Could have: Useful enhancements if capacity remains.
- Won't have now: Explicitly deferred to protect focus.

## Decision Output

When presenting a prioritization recommendation, include:

- Recommendation
- Why it ranks there
- What is being traded off
- What evidence is missing
- What should happen next
