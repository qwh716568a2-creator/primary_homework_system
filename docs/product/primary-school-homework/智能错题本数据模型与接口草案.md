# 智能错题本数据模型与接口草案

## 1. 设计原则

- 兼容现有错题本结构，不推翻 `wrong_book_item` 主表。
- 尽量复用已有 `status` 字段语义。
- 新能力通过“练习池字段 + 练习记录表”扩展。
- 第一版先服务学生端，不要求教师端复杂配置。

- 主表：[WrongBookItemPo.java](D:\primary_homework_system\back-end\src\main\java\com\primaryhomework\backend\entity\po\WrongBookItemPo.java)

## 3. 数据模型建议

### 3.1 方案一：在现有错题主表扩字段

建议在 `wrong_book_item` 增加以下字段：

- `pool_type` varchar(32)
  - 题池类型
  - 建议值：
    - `active_wrong`
    - `risky_correct`
    - `mastered_archive`
- `correct_streak` int default 0
  - 连续正确次数
- `mastery_score` decimal(5,2) default 100
  - 掌握度或权重分
- `practice_count` int default 0
  - 总练习次数
- `last_practiced_at` datetime null
  - 最近练习时间
- `last_practice_result` varchar(16) null
  - 最近练习结果
  - 建议值：`correct` / `wrong`
- `source_scene` varchar(32) null
  - 错题来源场景
  - 建议值：`teacher_mark` / `student_manual` / `practice_generated`

## 4. 状态模型建议

### 4.1 错题条目业务状态 `status`

沿用现有：

- `pending_fix`
- `fixed`
- `mastered`

### 4.2 练习池状态 `pool_type`

新增：

- `active_wrong`
- `risky_correct`
- `mastered_archive`

### 4.3 建议理解

- `status` 解决“错题条目本身当前处于什么阶段”
- `pool_type` 解决“这道题当前在练习引擎里该如何参与抽题”

## 5. 关键规则落表逻辑

### 5.1 新错题创建

- `status = pending_fix`
- `pool_type = active_wrong`
- `correct_streak = 0`
- `mastery_score = 100`
- `practice_count = 0`

### 5.2 学生完成订正

- 现有逻辑继续将 `status` 调整为 `fixed`
- 但不直接出池
- `pool_type` 仍可保持 `active_wrong`

### 5.3 练习做对

- `correct_streak + 1`
- `practice_count + 1`
- `last_practice_result = correct`
- `last_practiced_at = now()`
- `mastery_score = mastery_score - 20`

### 5.4 练习做错

- `correct_streak = 0`
- `practice_count + 1`
- `last_practice_result = wrong`
- `last_practiced_at = now()`
- `mastery_score = mastery_score + 25`
- `pool_type = active_wrong`

### 5.5 连续两轮做对

满足：

- `correct_streak >= 2`
- `mastery_score <= 30`

则：

- `pool_type = mastered_archive`
- `status = mastered`

### 5.6 已掌握题再次做错

- `pool_type = active_wrong`
- `status = fixed` 或 `pending_fix`
  - 建议第一版设为 `fixed`
- `correct_streak = 0`

## 6. 接口设计草案

### 6.1 生成练习计划

`GET /api/student/wrong-book/practice/plan`

请求参数：

- `subjectCode` 可选
- `questionCount` 可选，默认 10

响应示例：

```json
{
  "practiceId": 10001,
  "practiceName": "今日错题小练习",
  "questionCount": 10,
  "wrongQuestionCount": 8,
  "riskyQuestionCount": 2,
  "items": [
    {
      "practiceItemId": 1,
      "wrongBookId": 20001,
      "questionNo": "1",
      "subjectCode": "math",
      "questionText": "3/4 + 1/8 = ?",
      "correctAnswer": "7/8",
      "itemSourceType": "active_wrong",
      "itemWeight": 96.0,
      "sortNo": 1
    }
  ]
}
```

### 6.2 提交练习结果

`POST /api/student/wrong-book/practice/submit`

请求体示例：

```json
{
  "practiceId": 10001,
  "items": [
    {
      "practiceItemId": 1,
      "wrongBookId": 20001,
      "studentAnswer": "7/8",
      "resultStatus": "correct",
      "usedDurationSeconds": 18
    }
  ]
}
```

响应示例：

```json
{
  "practiceId": 10001,
  "correctCount": 8,
  "wrongCount": 2,
  "accuracyRate": 0.8,
  "masteredCount": 3,
  "returnedToActiveCount": 2
}
```

### 6.3 查询练习历史

`GET /api/student/wrong-book/practice/history`

请求参数：

- `pageNo`
- `pageSize`

### 6.4 查询单次练习详情

`GET /api/student/wrong-book/practice/{practiceId}`

## 7. 前端页面与接口对应

### 7.1 学生端页面

- 错题本首页
  - 新增练习入口
  - 调用：`GET /practice/plan`
- 练习作答页
  - 使用练习计划返回的题目
- 练习结果页
  - 调用：`POST /practice/submit`
- 练习历史页
  - 调用：`GET /practice/history`

### 7.2 家长端页面

- 可选查看孩子最近练习结果
- 第一版可直接复用练习历史接口的只读版本

## 8. 与现有接口的关系

保留现有：

- `GET /api/student/wrong-book`
- `GET /api/student/wrong-book/{wrongBookId}`
- `POST /api/student/wrong-book`
- `POST /api/student/wrong-book/{wrongBookId}/fix`
- `POST /api/student/wrong-book/{wrongBookId}/mastered`

新增后，不影响老接口继续工作。  
智能练习只是建立在现有错题数据之上的一层新能力。

## 10. 风险与建议

- 现有系统没有全量正确题库，所以 20% 风险正确题第一版要从“历史错题但最近做对”中取。
- 如果后续真的要覆盖“做对但其实不会”的更广泛情况，后面需要把常规作业作答记录沉淀成题目级练习画像。
- 第一版建议先证明机制有效，而不是追求绝对智能。
