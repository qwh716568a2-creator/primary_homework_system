# 小学课后作业系统数据库设计文档

## 1. 文档说明

- 文档目标：定义小学课后作业系统 MVP 阶段的数据库方案，供后端开发、DBA、测试和运维评审使用。
- 数据库类型：MySQL 8
- 存储引擎：InnoDB
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_general_ci`

## 2. 本次账号模型结论

本版采用“统一账户主表 + 角色资料分表”方案：

- `user_account`：统一账户主键、密码、角色、状态
- `student_profile`：学生资料和学号
- `teacher_profile`：教师资料和手机号
- `parent_profile`：家长资料和手机号

登录规则：

- 管理员：`user_account.login_name + password`
- 教师：`teacher_profile.mobile + password`
- 家长：`parent_profile.mobile + password`
- 学生：`student_profile.student_no + password`

设计原因：

- 保留统一用户主键，便于通知、日志、权限、操作记录统一引用
- 角色资料字段明显不同，拆表后结构更清晰
- 避免所有角色字段都堆在同一张用户表里

## 3. 设计原则

- 以学生为业务主体设计作业、提交、批改链路
- 聚合状态与流水记录分离，兼顾查询性能和可追溯性
- 账户表负责认证主键，资料表负责角色属性和登录标识
- 业务约束尽量通过唯一索引和应用层规则共同保证
- MVP 阶段不做分库分表

## 4. 命名规范

- 表名：小写下划线风格，例如 `student_homework_task`
- 主键：统一使用 `id bigint`
- 时间字段：统一使用 `created_at`、`updated_at`、业务时间使用 `*_at`
- 布尔字段：统一使用 `tinyint(1)`
- 状态字段：统一使用 `varchar(32)`

## 6. 核心关系说明

- 一个学校可包含多个年级和班级
- 一个账户对应一个角色类型
- 一个学生账户对应一条 `student_profile`
- 一个教师账户对应一条 `teacher_profile`
- 一个家长账户对应一条 `parent_profile`
- 一个教师可任教多个班级和学科
- 一个学生可绑定多个家长
- 一条作业可关联多个班级
- 一条作业发布后，将为目标学生生成多条 `student_homework_task`
- 一条任务可对应多次提交和多次批改

## 9. 关键业务约束

- 学生登录标识来自 `student_profile.student_no`
- 教师登录标识来自 `teacher_profile.mobile`
- 家长登录标识来自 `parent_profile.mobile`
- 管理员登录标识来自 `user_account.login_name`
- 同一学生在同一学校下学号唯一
- 同一教师手机号全局唯一
- 同一家长手机号全局唯一
- 一条作业可关联多个班级
- 一条作业发布后，必须为目标学生生成任务
- 一条任务允许多次提交，`version_no` 递增
- 批改记录必须绑定具体提交记录

## 10. 性能建议

- 教师作业列表重点依赖 `homework`、`homework_class_rel`、`student_homework_task`
- 学生首页重点依赖 `student_homework_task(student_id, task_status)`
- 学生登录重点依赖 `student_profile(school_id, student_no)`
- 教师登录重点依赖 `teacher_profile(mobile)`
- 家长登录重点依赖 `parent_profile(mobile)`
- 通知列表重点依赖 `notification_record(receiver_user_id, send_status, created_at)`

## 11. 扩展建议

- MVP 阶段不建议分库分表
- 后续若学校数量显著增加，可优先考虑对提交表、通知表、日志表做按时间归档
- 若进入多学校 SaaS 化阶段，可考虑按学校做逻辑隔离或分库演进
